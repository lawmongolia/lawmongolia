**IT салбарын өмгөөлөгч** хайж буй компанид ердийн гэрээний мэдлэгээс гадна программ хангамж хэрхэн бүтээгддэг, API хэрхэн холбогддог, SaaS үйлчилгээ ямар үзүүлэлтээр хэмжигддэг, өгөгдлийн лог юу нотолж болохыг ойлгох хууль зүйн дэмжлэг хэрэгтэй. Технологийн маргаанд гэрээний текст ба системийн бодит ажиллагаа хоёр зөрөх нь түгээмэл эрсдэл юм.

**Г.Итгэл** нь [LawMongolia дахь мэргэжлийн танилцуулгадаа](/mn/people/itgel-galsanjamts) технологи, дижитал платформ, финтек, компанийн гэрээ болон шүүхийн маргааны чиглэлээр ажилладаг өмгөөлөгч гэж танилцуулагдсан. Тус нийтлэлд IT байгууллагад тохиолдож болох ерөнхий маргааны төрлүүд, нотлох баримтын онцлогийг тайлбарлана; тодорхой үйлчлүүлэгчийн хэрэг, ялалтын үр дүнг ил болгохгүй.

## 1. Программ хөгжүүлэлтийн гэрээ: гүйцэтгэл дууссан эсэхийг юу нотлох вэ?

Систем ажиллаж эхэлсэн нь гэрээгээр тохирсон **бүх ажлыг хүлээлгэн өгсөн** гэсэн үг биш. Техникийн даалгавар, үе шатны акт, тестийн тайлан, алдааны бүртгэл, аюулгүй байдлын шалгалт, эх кодын репозиторийн нэвтрэх эрх, deployment баримт бичгийг харьцуулна.

Захиалагч “эх кодоо өгсөнгүй” гэж маргаж байхад хөгжүүлэгч “систем ажиллаж байгаа” гэж тайлбарлаж болно. Энэ нөхцөлд хүлээлгэн өгөх үүргийг функциональ үр дүн, эх код, лиценз, нэвтрэх эрх, баримт бичиг гэсэн тус тусдаа ангиллаар шалгах шаардлагатай.

## 2. Зохиогчийн эрх: программын автор ба ашиглах онцгой эрхийг ялгах

[Зохиогчийн эрхийн тухай хуулийн 22.1–22.3](https://legalinfo.mn/mn/detail/16230812154721) нь компьютерын программын зохиогч, ажил үүргийн дагуу болон захиалгаар бүтээсэн программын ашиглах онцгой эрхийн талаар тусгай зохицуулалттай. Захиалгаар бүтээсэн программын ашиглах онцгой эрхийг гэрээнд өөрөөр заагаагүй бол захиалагч эдлэхээр хуульчилсан.

Гэхдээ энэ нь хөгжүүлэгчийн өмнө ашиглаж байсан бүх модуль, open-source сан, гуравдагч этгээдийн төлбөртэй лицензийн эрх нэгэн зэрэг шилжинэ гэсэн үг биш. Өмгөөлөгч гэрээ, кодын бүрэлдэхүүн, лицензийн жагсаалт, төслийн түүхийг хамтад нь үнэлэх шаардлагатай.

## 3. SaaS ба SLA: тасалдлыг хэрхэн баримтжуулах вэ?

SaaS (software as a service) гэрээнд uptime, төлөвлөгөөт засвар, хүлээгдэж буй хариу өгөх хугацаа, data backup, incident response, үйлчилгээний кредит, төлбөр буцаалт, гэрээг цуцлах нөхцөлийг тодорхойлдог. Маргаан үүсэхэд нэг талын screenshot-оос илүү server monitoring, incident ticket, uptime тооцооллын арга, мэдэгдэл хүргэсэн хугацаа чухал болж болно.

Жишээ нь, 99.5 хувийн uptime тохиролцсон бол аль хугацааны интервал, ямар хасалт, ямар хэмжилтийн эх сурвалжаар тооцохыг гэрээнээс нягтална. Энэ бол жишээ бөгөөд LawMongolia-ийн стандарт SLA эсвэл бодит хэргийн баримт биш.

## 4. API болон гуравдагч этгээдийн интеграц: хэн алдаа гаргасныг тогтоох

API доголдол, буруу хаягжуулалт, буруу тарифт тооцоо, duplicate call, webhook хүрээгүй, third-party provider тасалдсан зэрэг асуудалд нэхэмжлэлийн эрх зүйн үндэслэлээс өмнө техникийн шалтгааныг баримтжуулна. Request ID, timestamps, HTTP status, payload-ийн хувилбар, integration specification, retry logic, authentication log зэрэг нь хариуцлагыг хуваарилахад чухал.

Гэрээнд API call-ийн тооцоолол, SLA, call limit, rate limit, access key-ийн хариуцлага, гуравдагч этгээдийн үйлчилгээ тасарсан үеийн эрсдэлийг тодорхой тусгасан эсэхийг шалгана.

## 5. Хувийн мэдээлэл ба кибер зөрчил: технологийн асуудал нь эрх зүйн асуудал мөн

[Хүний хувийн мэдээлэл хамгаалах тухай хууль](https://legalinfo.mn/mn/detail/16390288615991) нь мэдээлэл цуглуулах, боловсруулах, ашиглах хууль ёсны үндэслэл, мэдээллийн эзний эрх, мэдээлэл хариуцагч болон боловсруулагчийн үүргийг зохицуулдаг. [Кибер аюулгүй байдлын тухай хууль](https://legalinfo.mn/mn/detail/16390365491061)-ийн шаардлагыг тухайн байгууллагын үйл ажиллагаа, эрх зүйн статустай уялдуулан үнэлнэ.

Мэдээлэл алдагдсан байж болзошгүй тохиолдолд access log, permission change, cloud audit, incident timeline, өгөгдлийг хэн, ямар үндэслэлээр боловсруулсан зэрэг баримтыг хадгалах хэрэгтэй. **Нууцлалын гэрээ** ганцаараа мэдээлэл хамгаалах бүх хууль ёсны үүргийг орлохгүй.

## 6. IT компанид өмгөөлөгч хэзээ, технологийн зөвлөх хэзээ хэрэгтэй вэ?

Системийн доголдлыг шинжээч буюу инженер техникийн хувьд дүгнэнэ. Өмгөөлөгч нь техникийн дүгнэлтийг гэрээний үүрэг, хариуцлага, нотлох баримтын журам, шүүхийн шаардлагатай холбодог. Нэг хүнийг хоёр мэргэжлийн бүх ажлыг дангаар гүйцэтгэх ёстой гэж үзэх нь буруу; шаардлагатай бол техникийн шинжээч, мэдээллийн аюулгүй байдлын багтай хамтран ажиллана.
